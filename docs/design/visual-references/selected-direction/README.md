```text
sunlit-editorial-public.png
```

They are supporting design evidence for the canonical Sunlit Editorial direction. Their presence does not make them production assets or pixel-perfect implementation specifications.

## Authority

The approved references are evidence for:

- overall visual character;
- public vs authenticated expressive intensity;
- editorial composition principles;
- trust/information hierarchy;
- restrained editorial-yellow usage;
- relationship between real imagery, typography, and structured progress;
- the Evidence Journal concept.

They are **not** authority for:

- business/domain behavior;
- API shape;
- exact route structure;
- component decomposition;
- CSS/Tailwind strategy;
- exact responsive geometry;
- exact production content/data;
- product states or evidence claims shown only as illustrative reference content;
- pixel-perfect reproduction.

Reusable concrete system behavior such as approved colors, typography roles, spacing posture, radius/elevation, icon baseline, and progress/provenance grammar is owned by `../../design-guidelines.md`, not reconstructed from screenshots.

If a visual detail conflicts with product/domain truth, product/domain truth wins.

## Interpretation rule

A healthy translation asks:

- Is the information hierarchy equivalent in intent?
- Does the interface feel like one Sunlit Editorial system?
- Is optimism supported by evidence rather than decoration?
- Are fact, report, state, and uncertainty distinguishable?
- Does public expression become appropriately calmer in product UI?
- Would realistic content and edge cases still work?

Do not reproduce an illustrative label, number, campaign, organization, image, or state unless canonical product/API data supports it.
