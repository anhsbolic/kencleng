## What & why

Rencana ini merekonsiliasi batas donasi individual per Campaign dan kapasitas kumulatif agar setiap Donation yang diterima dapat diselesaikan penuh tanpa melampaui kapasitas Campaign. Arah kebijakan telah diputuskan; Techplan mengatur rekonsiliasi source dan bukti lanjutan, tanpa menyatakan source telah diterima atau implementasi telah selesai.

## Scope

**Included**
- Cap whole-IDR per Campaign Rp5.000–Rp1.000.000.000, default Rp1.000.000.000; Owner/Staff mengatur saat draft dan nilainya dibekukan saat publikasi.
- Disclosure cap pada public detail dan pemeriksaan ulang independen saat Donation POST.
- Reservasi settled Funding ditambah accepted-pending Donation terhadap batas representasi Campaign; close saat kapasitas habis dengan `funding_capacity_reached`.
- Pelunasan penuh dan tepat sekali untuk accepted-pending Donation setelah close; kegagalan tidak membuka ulang Campaign.
- Handoff perilaku public closed-Campaign ke Slice 3, sambil mempertahankan perilaku 404 Slice 2.

**Explicitly not included this round**
- Backend/frontend implementation, migrations, DB application, generators, tests, runtime/browser checks, atau pemilihan mekanisme transaction/locking.
- Perubahan Tier-0, kebijakan presisi/range uang universal, settlement pembayaran nyata, atau paparan kapasitas tersisa/alasan internal.
- Aktivasi closed-Campaign detail visibility pada Slice 2 atau penyelesaian delivery Slice 3.
- Penerimaan source changes, risk acceptance, approval Techplan, atau milestone delivery.

Owning authorities meninjau dan menerima source changes serta counterpart yang diperlukan. Setelah source konvergen, backend dan frontend menjalankan Techplan refresh terpisah dengan bukti delivery/runtime masing-masing.

## Interface Contract

Plan ini menambah dan mengubah kontrak lintas Product, Campaign/Donation, authored API, consumer, dan persistence. Arah kontrak berikut sudah dipilih owner; source acceptance konkret masih pending.

| Concern | Contract |
|---|---|
| Endpoint / interface | `POST /organizations/{organizationId}/campaigns`; `PATCH /campaigns/{campaignId}`; public `GET /campaigns/{campaignId}`; `POST /campaigns/{campaignId}/donations`; Campaign persistence dan public detail projection. |
| Authentication / authority | Owner/Staff dapat mengatur cap saat Campaign draft; setelah publication cap tidak dapat diubah dalam Slice 2. API authorization konkret mengikuti source pemiliknya. |
| Trigger / caller | Campaign create/update oleh pemilik berwenang; guest membaca public detail sebelum memasukkan amount dan mengirim Donation; POST melakukan pemeriksaan eligibility dan cap secara independen. |

**Request / input**

| Field / input | Meaning / requirement |
|---|---|
| `max_donation_amount` pada create/PATCH | Opsional; whole-IDR Rp5.000–Rp1.000.000.000. Jika create menghilangkan field, default Rp1.000.000.000; jika PATCH menghilangkannya, nilai tersimpan dipertahankan. Nilai yang diberikan hanya dapat diatur saat draft. |
| `amount` pada Donation POST | Diperiksa ulang terhadap eligibility dan cap saat ini; nilai di atas cap menghasilkan shared generic `422 ValidationError` pada field `amount`. |

Contoh bentuk input konseptual yang didukung plan (nilai amount tetap dalam format uang yang sudah berlaku):

```json
{
  "max_donation_amount": "1000000000"
}
```

Plan tidak membakukan payload penuh atau contoh error; gunakan schema aktual saat source reconciliation.

**Response / output**

| Field / output | Meaning |
|---|---|
| `max_donation_amount` pada Campaign response dan public detail | Wajib hadir; public detail mengungkap cap aktif sebelum amount entry. |
| `donation_action` | Semantik snapshot WU-S2-005 tetap; GET bukan otorisasi, POST authoritative. |
| `funding_capacity_reached` | Close reason Campaign yang berbeda dari threshold `max_amount_reached`; tidak dipublikasikan sebagai detail internal. |

Plan tidak menetapkan contoh response penuh. Public error tetap generik dan tidak mengungkap kapasitas tersisa atau alasan close internal.

**Error behavior:** Donation POST di atas cap menggunakan shared generic `422 ValidationError` pada `amount`; eligibility dan cap diperiksa independen saat POST. Perilaku closed/non-public detail tetap 404 di Slice 2. Detail mekanis response mengikuti shared schema saat source reconciliation.

**Persistence / compatibility:** Campaign menggunakan representasi saat ini `NUMERIC(19,2)`, dengan batas whole-IDR `99,999,999,999,999,999`. Existing rows diarahkan untuk backfill ke Rp1.000.000.000 sebelum cap-dependent behavior diaktifkan. Kolom/type persis, backfill, rollout, rollback, dan penerapan DB belum diputuskan oleh plan ini dan perlu source/delivery ownership. Response field baru dapat memengaruhi strict decoder; generated types, fixtures, bundle, konsumen, dan kompatibilitas wajib ditinjau sebelum source acceptance.

## Key decisions

| Decision | Why / consequence |
|---|---|
| `max_donation_amount` opsional pada create/PATCH; omission create memakai default Rp1 miliar; omission PATCH mempertahankan nilai tersimpan. | Keputusan owner 2026-10-01; menjaga unrelated partial update tidak mereset cap. Concrete source acceptance masih diperlukan. |
| Batas kapasitas menghitung settled Funding dan accepted-pending Donation; kapasitas penuh menutup Campaign dengan `funding_capacity_reached`. | Menjamin Donation yang diterima dapat diselesaikan penuh; berbeda dari `max_amount_reached` yang tetap threshold overshootable. |
| Perilaku public closed-Campaign ditangani Slice 3; Slice 2 mempertahankan 404. | Membatasi scope aktif dan menjaga tindak lanjut Product/spec/API tetap eksplisit. |
| Shared monetary standard tetap format-only. | Tidak menetapkan range atau scale universal baru. |

## Material risks / trade-offs

| Risk / trade-off | Exposure / mitigation | Status |
|---|---|---|
| Concurrent admission/settlement dapat over-reserve atau membuat Donation yang diterima tidak bisa diselesaikan. | Wajib ada bukti PostgreSQL concurrency/runtime pada delivery/testing berikutnya; mekanisme tetap delivery-owned. | Open downstream |
