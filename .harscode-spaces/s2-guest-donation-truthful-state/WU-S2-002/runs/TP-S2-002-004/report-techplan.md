## Interface Contract

Techplan menetapkan area kontrak lintas layer yang harus direkonsiliasi, tetapi belum mengunci endpoint, field, header, status code, maupun bentuk credential karena bergantung pada Open Items. Tidak ada contoh request/response final yang dapat dicantumkan tanpa mengarang keputusan.

| Concern | Contract |
|---|---|
| Authored API | `api/openapi/donation.yaml`, dengan registry di `api/openapi/index.yaml` dan shared components dari `api/openapi/common.yaml` hanya bila dirujuk. |
| Authentication / authority | Guest submission dan safe revisit harus didefinisikan; backend berwenang atas eligibility dan persisted state. Settlement/result transition tidak boleh menjadi HTTP action yang dapat dipanggil client. |
| Trigger / caller | Guest memulai submission; caller/status access dan credential carrier menunggu keputusan O1–O5. |
| Persistence / money | State sukses dan refleksi funding harus menjadi satu hasil bisnis atomik dan concurrency-safe; setiap kontribusi sukses tercermin tepat sekali, termasuk settlement replay. Mekanisme implementasi tidak dikunci. |

**Request / input:** Field submission, amount semantics, payment representation, dan retry policy belum difinalkan. O1 dan O9 menahan acceptance contract yang bergantung padanya.

**Response / output:** Status/result harus merepresentasikan state sandbox yang persisted tanpa mengesankan settlement eksternal. Bentuk status dan safe revisit menunggu keputusan terkait.

**Error behavior:** Kegagalan validation/business serta status failure/parity harus ditetapkan dalam rekonsiliasi; Techplan tidak memilih response shape historis `401` atau `404` sebagai keputusan aktif.
