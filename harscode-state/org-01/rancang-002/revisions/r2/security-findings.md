## Findings dan disposition

### SEC-R2-01 — MEDIUM — Preview FK membuat intended deletion gagal

**Original producer checkpoint:** solution `c6c324707bdf3ea9d8f8011a0487ac67c797ff717f1057bfd46e03b3f8dbf62a`, R2-B step6 memerintahkan refresh→sessions→previews. R2-D menambah `account_deletion_previews.session_id` FK RESTRICT ke sessions. Setiap actionable confirmation mempunyai preview child; session DELETE akan gagal sebelum preview dibuang. T05-C/E dan approved simple deletion membutuhkan coherent erasure order. Akibatnya rollback terjadi sesudah intent diterima; account tetap fenced dan penghapusan tidak selesai.

**Response:** Security melaporkan ke Architect/Coordinator, tidak mengedit producer. Architect mengubah B6: seluruh previews account, termasuk session lain, dihapus sebelum sessions. R2-C early-ended family cleanup menghapus session-bound previews dahulu. TECH08 menambah actual FK current/other-session order, negative wrong-order rollback dan early cleanup. Correction `9899332ec152e0503d322734ab660fce1e3a409b2eadc81e87c3596b413059ae` dibuka langsung; final checkpoint mempertahankannya dan TECH10 enum urutan diselaraskan.

**Disposition: ADDRESSED AT DESIGN LEVEL.** Runtime FK/erasure closure **NOT VERIFIED**. Tidak ada waiver atas FK/integrity atau silent cascade.

### OBS-R2-02 — MEDIUM design seam, disurfacing Koordinator — Callback melampaui marker lifetime

Pada checkpoint sebelum correction, batas attempt5m belum eksplisit mengikat effect sesudah Google I/O/lock wait. Jika payload tervalidasi dipakai setelah expiry dan deletion fence retired, stale attempt berpotensi provision/session kembali. Ini berbeda dari deliberate fresh normal login yang diizinkan sebagai account baru.

Security memeriksa sendiri correction producer pada final solution R2-A dan TECH01: expiry recheck sesudah Google network I/O **dan** identity/account lock wait tepat sebelum lookup/provision/session issuance; copied payload tidak melewati deadline, bounded protocol/DB execution rollback setelah deadline. TECH01 menuntut delayed exchange/lock-past5m termasuk ketika fence sudah dapat dipurge.

**Disposition: ADDRESSED AT DESIGN LEVEL, runtime NOT VERIFIED.** Origin concern Koordinator, bukan klaim Security menemukan sendiri atau test exploit.
