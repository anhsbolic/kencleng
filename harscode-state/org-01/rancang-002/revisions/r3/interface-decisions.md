## Struktur, invariants dan data ownership

Modular monolith Go/net/http/pgx/PostgreSQL, satu schema `public`; identity dan organization modules hanya muncul untuk kebutuhan ini. Identity owns account/mapping/session/attempt/proof/deletion orchestration; organization owns organization/Owner/receipt dan menyediakan operasi dalam `pgx.Tx` yang sama: `InspectSimpleOwnedContexts(tx,account)` dan `EraseConfirmedContexts(tx,exactIDs)`. Organization create owns transaksi bersama identity's effective-account/session operation, tanpa SQL bypass. Tidak menambah event bus, generic role engine, admin API, identity broker, object storage atau Worker framework. Reconciliation membutuhkan bounded trusted execution, bukan browser privilege.

## Wire choices, input and cookie transport

OpenAPI is self-contained OpenAPI3.0.3; no custom DSL. `operationId`s are unique and exactly11. Unprefixed backend paths are authoritative path shapes, browser calls `/api` ingress. Creation201 Location `/organizations/{id}` is a backend resource reference, not frontend navigation or directly fetchable browser URL. Browser client uses response data.organization.id with explicit `/api/organizations/{id}` in its typed transport, and never blindly follows Location; no ingress Location rewrite assumed. Callback303 Locations are fixed frontend navigation routes. UI redirect destinations are requirements for frontend pages, not new backend operations. All response bodies use `{data,meta?}` except problem JSON,204 and303. All objects closed, every field required unless explicitly optional, **no field nullable**. List is `{data:[{organization,owner}],meta?:{nextCursor}}` (no nested data per item); omit meta on final page. Session response only accountId+csrfToken. Date-times UTC RFC3339 `Z`; UUID identity comparisons case insensitive; output canonical lower case. Response name is canonical. Cursor unpadded base64url of UTF-8 JSON `[createdAt,id]`; validated only as position, cannot grant access. List is live keyset not snapshot; concurrent new higher-position orgs may not appear on later pages, removed rows may disappear. Start fresh list for current discovery; name matching never confirms an unknown key.

Every response including errors/redirects: `Cache-Control: no-store`. JSON body caps are UTF-8 bytes, independent of codepoint validation: auth/preview/confirm1024, create4096; preview output65536. Required JSON, no duplicate keys, no unknown members/parameters or repeated singleton headers, except the bounded provider callback extension-query rule below. Invalid type/body/encoding/size/UUID/media/query/header→400 invalid-request. Canonical name trim uses Unicode White_Space at edges, retains case/internal whitespace;1..200 Unicode codepoints and no Unicode Cc controls. Semantic name invalid→422 validation with fixed allowed field messages, no input echo. Validate `Idempotency-Key` UUIDv7 and future<=5m; request-path UUIDv7 validation does not require current admission time. Rate/admission guards are feature-local: Google attempts use a per-process maximum128 outstanding unexpired memory attempts (no caller/browser bucket); when full return429 with Retry-After bounded to1..60seconds until earliest expiry/capacity release. The callback-scoped binding cookie is intentionally not available to the attempts POST and cannot be a quota identity. Creation30/effective-account/minute and preview10/effective-account/minute use bounded one-minute counters, return429 Retry-After1..60 before new effect; purge expired counters. These technical capacity safeguards are not Product org-count/eligibility rules, strong anti-abuse assurance, or durable per-person limits; no IP/UA/new tracking cookie. Restart resets admission memory but never resets session/receipt/fence/atomicity authority.

| Name | Browser Path | Value / TTL |

Nonlocal requires effective HTTPS and explicit trusted proxy/ingress; local Secure=false only effective local plus actual loopback browser-facing ingress, otherwise startup fails. Names intentionally work with both authorized profiles, no Secure-prefix misuse. Multiple **separate Set-Cookie lines**, never comma joined; OAS describes string header only because repeated transport lines are not representable as a conventional comma-array. Clear by empty value, Max-Age=0, Expires=Thu, 01 Jan 1970 00:00:00 GMT, same Path/host/HttpOnly/SameSite/Secure. Logout clears access+refresh+attempt; deletion200 also clears all three. Paths require browser ingress `/api`; production ingress must bind same prefix before use, cannot silently alter Paths.

Duplicate same-name auth cookie occurrences are rejected (401 on protected API;303 failure callback). Never select first/last duplicate. Startup/adoption must ensure no same-name cookie at other Path/Domain and no old legacy cookie collision; server cannot infer unreceived broader-path tuples or delete arbitrary Domain cookies. Ambiguous collision is not weaker-cookie fallback. Duplicate request Cookie header lines may be parsed as normal combined cookie list, but duplicate target names remain invalid. Origin missing/null/multiple/mismatch→403 on all JSON mutations, including harmless logout repeat. No cross-origin CORS credentials grant, no form fallback. Cookie scheme is OAS apiKey syntax, not extra application API key.

## Identity, conditional proof and precedence

Backend validates RS256 only, trusted kid allowlist, signature/issuer/audience/sub internalUUID/sid/iat/exp, no arbitrary key fetch. No roles/PII in JWT. Old verifier keys retained until their access tokens expire. Each protected boundary checks account exists, current session not revoked/expired and no journal fence; JWT alone insufficient. Identity locks before account lock, account before session (multiple sessions sorted IDs), then request/receipt/org locks, using PostgreSQL transaction locks. Never acquire identity after account. Journal lookup unknown fails closed, not absent. No network Google inside DB create transaction.

Google start `{}` is intentional normal login: exact Origin+JSON prelogin defense, no session requirement/CSRF, no account mutation yet. `{purpose:deleteAccount}` requires valid **access** authority+session CSRF, stores expected account and start time, invalidates old actionable deletion previews for that session. `{purpose:null}`, login purpose string or client accountId invalid400. Optional CSRF header in OAS is conditionally mandatory in proof branch; security alternatives do not make proof anonymous. State/nonce/PKCE+binding are random, server-owned; maintained OIDC validation covers issuer/audience/signature/expiry/nonce/code replay. Provider issuer+sub unique mapping, never matching email. Normal first login atomically creates account+mapping; existing login reads it. Special callback only exact expected existing account, never provision/merge/link, marks new session proof at attempt started_at. Cancellation/mismatch/expiry invalidates old relevant previews, creates no deletion intent/effect. Callback query requires exactly one state and exactly one of code/error; duplicate security parameters or malformed encoding fail safely. Ignore provider extension parameters (scope/authuser/prompt/error_description/error_uri and other names) as non-authoritative, never claims or scope authority, never reflected/logged. Total raw request-target<=8192 bytes, <=16 query pairs, decoded names<=64bytes, extension values<=2048bytes; bounds failure→303 failure. Unknown extensions may repeat within total bound because they have no authority. Required code<=4096chars/state<=256chars/error<=128chars constraints still apply. This bounded callback-only exception accommodates [Google’s documented callback containing scope](https://developers.google.com/identity/openid-connect/openid-connect#confirmxsrftoken) without collecting profile data or widening requested openid scope; provider interoperability remains NOT RUN. All callback failures redirect fixed `/auth/failure`; normal success `/auth/complete`, proof success `/account-deletion/review`. No query-string token, error echo, returnTo or auto-submit. Failure page explicit choices preserve any earlier creation/deletion unknown state; failure of this flow does not prove earlier operation failed.

Attempt expires5m **through final effect** (now>=started_at+5m is expired): check after Google I/O and again after identity/account lock waits immediately before lookup/provision/session issuance; rollback if expired. Memory one-use consume prevents replay, restart safely fails. Journal pending intent blocks matching identity callbacks; applied intent rejects attempts started<=cutoff. After verified erase, explicit new normal flow may create a new UUID with no old contexts, sessions, keys or receipts. It is not recovery. Journal outage blocks provisioning. Callback already holding identity lock finishes before deletion, which then erases its newly issued session too.

GET session evaluates access first. Valid live access wins (refresh ignored, even consumed refresh); absent or **expired-only otherwise authentic** access permits unused refresh bootstrap. Invalid syntax/signature/claims, account mismatch, revoked/deleted/fenced access never falls through. Refresh bootstrap validates unused verifier/current account+family/idle/absolute expiry without consume, rotate, idle extension or cookie issuance. Consumed refresh on GET gives401 without mutating family; actual POST refresh owns replay revoke. If both credentials supplied, a bad/duplicate access is not rescued by refresh. Bootstrap returns CSRF only and does not authorize organization/deletion writes. GET session200 deliberately does not disclose whether access or refresh bootstrap was used. On an access-required operation401, FE may GET session for current CSRF, then perform one user-directed/single-flight POST refresh and recheck principal via GET session; never automatically resubmit create/delete. If GET session401, require explicit sign-in choice; preserve any prior operation uncertainty. This sequence also handles reload without storing tokens.

POST refresh Origin/body validation precedes effective refresh authentication, then CSRF, then atomic consumed-verifier check/rotate. An authentic consumed verifier linked to still-live session lets CSRF be verified before replay revokes family; missing/bad CSRF403 must not revoke it. If no live family401; unknown DB/journal503 unavailable; ambiguous issuance503 result-unknown. One predecessor→one successor; concurrent loser revokes whole family, no replay grace. FE single-flight per tab and cross-tab coordination where available; response loss never blind replay old refresh. CSRF derived base64url HMAC-SHA256 dedicated key over domain separator+sessionUUID+nonce; stable across refresh/tabs, recoverable via GET session. Key rollover may cause403; re-GET session then actor-directed exact mutation retry with original creation key, never fresh-key automation.

POST logout resolves all provided **cryptographically verifiable** access/refresh credentials to their session before claiming no authority. Valid refresh-only must revoke its live family, including expired access fallback; invalid access combined with a valid refresh is401 (not weaker fallback). Both valid credentials pointing different sessions→401, no revoke/clear-success. Live session requires CSRF then durable revoke204. Fully absent/invalid-only credentials, or known revoked/expired/fenced/deleted session with no live authority→204 local cookie clear after Origin+JSON; no deleted-session CSRF needed. Duplicate cookies→401, not this repeat exception. Unknown DB/fence state→503; ambiguous revoke→503 result-unknown. Thus204 means current resolved authority absent/ended, not proof of when earlier response committed. On failed/unknown logout FE clears private memory/markers but reports server revocation uncertainty; it must not assert remote completion from local clearing.

For other JSON protected mutations order: Origin/content/body structural validation→effective access/account/fence→CSRF→semantic authorization/proof/preview/name/key→locks and same checks at effect boundary. Reads have no Origin/CSRF requirement, but cookie/account/fence validation remains. A known fenced/deleted account returns401 on reads/create/refresh/preview/confirm, including late retries; logout harmless clear is the sole204 exception. Existing known intent reconciliation is trusted backend work, never permission to bypass expired user authentication. Generic malformed shape may return400 without identity disclosure; do not use semantic resource errors before authentication. Multiple simultaneous failures follow this order; no mutation before required checks.

## Journal, retention, restore and release dependencies

Journal protected independent store fields minimum intentUUID, old accountUUID, exact orgUUID set, confirmedAt, HMAC(dedicated key, canonical issuer+subject)+key version, immutable applied checkpoint if available, affected-backup expiry evidence reference. No raw issuer/subject/name/email/profile. If more verified identities exist enumerate all. Pseudonymous personal metadata; access limited erasure/reconciliation and authorized restore operator, never browser/raw log/analytics.

Required vendor-neutral operations: PutConfirmedIntent(id,immutablePayload) idempotent exact equality, mismatch reject, durable ack or unknown; FindByIdentityFence/Account/Intent current/linearizable enough to fence, unavailable fail closed; MarkApplied only after primary inspection; EnumerateConfirmedAfter(restorePoint) complete with independent monotonic coverage watermark. Atomic writes survive selected active DB rollback/loss. Provider is unselected; sidecar in same rollback domain insufficient. Authorized reconciliation principal only `applyConfirmedDeletionIntent`, from verified durable payload+current dependency checks; no arbitrary global admin/session impersonation.

Before append known rollback→not accepted. Append unknown→query same intent: definitive absent not accepted, present accepted/fenced+apply, unable to determine remains unknown/held. Durable append then crash/rollback→accepted/fenced, idempotent apply without user session. Commit unknown→primary inspection with intent decides; rows still there retry same intent/checks. Applied-ack failure after erase→active erase remains effective, conservative restore replay pending. No accepted intent can be removed/cancelled by active rollback.
